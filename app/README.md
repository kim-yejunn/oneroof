# OneRoof — 관련 거래처·판매장려금 지급 통제

AX 인재전쟁 ONLINE · 삼일PwC 회차, 업무 **W07 관련 거래처와 판매장려금 지급**.

> 이름은 달라도 한 지붕이면 한도도 하나.

Corevia 대리점 판매장려금을 지급하기 전에 관련자 그룹을 판정하고, 그룹 합산으로 한도와 승인권자를 정하고,
승인·소명·상계·지급·은행 회신까지 상태를 이어 바꾸는 운영 시스템입니다.

## 무엇을 하나

| 단계 | 시스템이 하는 일 | 사람이 하는 일 |
|---|---|---|
| 접수 | 한 달 미지급 장려금을 받아 중복 접수를 거른다 | 영업지원팀이 정산 접수 |
| 확인 | 대표자·주소·정산계좌(실제 입금 계좌 포함) 2개 이상 일치를 전이적으로 묶어 관련자 그룹을 계산한다 | — |
| 판단 | 그룹 월 합산이 200만원을 넘으면 영업임원, 아니면 영업지원팀 전결로 상신한다 | — |
| 승인 | 권한 없는 역할의 결정은 서버가 거부한다 | 영업지원팀·영업임원·회계·자금팀이 결정 |
| 상태 변경 | 지급 지시, 보류, 상계, 은행 전송, 회신 반영, 감사 이관 | 대리점·은행 회신은 모의 입력 |

### 세 가지 상황

1. **정상**: 6월 40건 중 37건 전결, 관련자 그룹 RPG-D-011(D-011·D-024·D-037) 합산 3,888,097원은 영업임원 승인.
2. **조건 변경**
   - D-041 주소 정정 → D-034와 새 그룹 → 결정 전 검토 재분류, 지난달 전결분 사후 확인 요청.
   - 연체 대리점 입금 → 상계 제안 갱신·철회.
3. **정보 부족·승인 거절**
   - 지급 계좌 미확인 → 보류와 대리점 확인 요청.
   - 그룹 반려 → 관계 소명 요청 → 재상신 → 재반려 시 감사 이관.
   - 상계 이의 → 회계·자금팀 재검토.

### 필수 확장과 다른 부서 영향: 연체 미수금 상계

- 91일 넘게 연체된 대리점의 장려금은 영업 승인 뒤에도 바로 보내지 않습니다.
- 회계·자금팀이 **상계** 또는 **전액 지급 후 별도 회수**를 고릅니다.
- 상계는 몰수가 아니라 같은 금액의 미수금을 함께 소멸시키는 것이고, 법인 단위로만 합니다(민법 제492조).
- 계약 근거 없는 장려금 미지급은 대리점법상 불이익 제공이므로(공정위 2024-04 가구 3사) 시스템이 자동으로 깎지 않습니다.
- 원본 기준 6월: 21곳 20,806,770원 상계 대상, 현금 지급 37,159,812원 → 16,353,042원.

### AI: 대리점 회신 해석

- 대리점 회신(관계 소명, 상계 이의, 계좌 확인)이 들어오면 AI가 다음 항목으로 구조화합니다:
  - 요지, 회신 성격, 사유
  - 언급한 증빙, 적힌 금액
  - 답하지 않은 것, 확인할 일
- 결과는 결정권자에게 참고 자료로만 보여주고, 승인·지급 판단에는 쓰지 않습니다.
- 회신 원문에 없는 금액·증빙은 검증에서 빠집니다.
- 모델이 실패하면 규칙 기반 해석으로 대체합니다.
- 제공자는 설정으로 바꿉니다: Gemini 무료 키(OpenAI 호환 형식), 규칙 기반.

## 원본과 가정

- 원본 데이터(`01_참가자_배포용/04_원본데이터`)는 읽기 전용입니다. 필요한 파일만 `src/main/resources/original/` 에 복사했고, 체크섬을 테스트로 검증합니다.
- 화면과 감사 로그의 모든 값에 출처가 붙습니다: 원본 / 부서 주장 / 가정 / 모의 회신 / 계산 결과 / AI 생성.
- 교육용 가정 목록
  - 지급 계좌 확인: 실입금 계좌가 등록 정산계좌와 다르면 지급 전 대리점에 확인
  - 소명·확인 회신 기한 7일
  - 상계 조항이 대리점 계약서에 있다고 가정, 대상은 90일 초과 연체분
  - 기준일 2026-07-01

## 실행

```bash
docker compose -f compose.dev.yaml up -d                      # 로컬 Postgres (포트 54329)
JAVA_HOME=$(/usr/libexec/java_home -v 17) ./gradlew test      # 테스트 (Docker 필요, 모델은 호출하지 않음)
docker build -t oneroof . && docker run --rm -p 18080:8080 --env-file .env \
  -e DATABASE_URL='postgres://oneroof:oneroof@host.docker.internal:54329/oneroof?sslmode=disable' \
  -e DIRECT_DATABASE_URL='postgres://oneroof:oneroof@host.docker.internal:54329/oneroof?sslmode=disable' \
  oneroof
```

- AI 키는 `.env`(git 무시)에 둡니다. 형식은 `.env.example` 에 있습니다. 키가 없으면 규칙 기반으로 동작합니다.
- 화면: `http://localhost:18080`, API 문서: `/swagger-ui.html`.
- **시연 도우미** 메뉴에서 초기화와 단계별 실행을 할 수 있습니다. 같은 동작을 각 화면에서 직접 할 수도 있습니다.

## 구조

Spring Boot 4 · Java 21 · Spring Modulith · JPA · Flyway · PostgreSQL, 화면은 React · Vite · Tailwind.

- 모듈 사이 상태 전파는 이벤트로 하고, 이벤트는 같은 트랜잭션의 발행 기록에 저장됩니다(Transactional Outbox).
  - 막힌 처리는 2분 뒤 다시 보냅니다.
  - 완료 기록은 하루 뒤 지웁니다.
- 일괄 처리는 사용자 행동 하나가 이벤트 하나가 되도록 묶음 단위로 흐릅니다.
- 외부 연동(은행, 대리점 통지, AI)만 포트·어댑터로 둡니다. 은행과 통지는 모의 어댑터입니다.
