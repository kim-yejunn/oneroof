## 풀려고 한 문제

대리점 판매장려금은 한 건씩 보면 모두 한도(200만 원) 아래였습니다. 하지만 대표자·주소·계좌가 겹치는 대리점을 한 거래처로 묶으면 이야기가 달라집니다.

- 원본 데이터: 대리점 50곳, 장려금 240건(2026-01 ~ 06), 입금 이력 32건
- 관련자 그룹 D-011·D-024·D-037
  - 대표자가 같고 주소와 계좌도 일치합니다.
  - D-024의 실제 입금 계좌는 등록 계좌와 다르고, D-011의 계좌와 같습니다.
- 개별 건은 최대 1,867,253원이지만, 그룹으로 합산하면 매달 3,888,097 ~ 4,870,186원입니다. 한도의 약 2배입니다.

## AI를 쓴 곳과 쓰지 않은 곳

- 판정, 합산, 승인권자 결정, 상계 계산은 모두 결정적 코드로 처리합니다. 승인과 반려는 사람이 합니다.
- AI는 대리점이 자유 텍스트로 보낸 회신을 정해진 형식으로 정리하는 데만 씁니다.
  - 형식: 요지, 성격, 사유, 증빙, 금액, 미답변 항목, 확인할 일
  - 결과는 JSON으로 검증합니다. 원문에 없는 금액이나 증빙은 지웁니다.
  - 모델 호출이 실패하면 규칙 기반 해석으로 대신합니다.
  - 모델은 Gemini 무료 API(OpenAI 호환 형식)입니다.
- 결정 화면에서 결정권자가 확인한 항목은 결정 사유와 감사 로그에 남습니다. 그래서 AI 정리 결과가 실제 판단에 어떻게 쓰였는지 추적할 수 있습니다.

## 구조

- 기술: Spring Boot 4.1 · Java 21 · Spring Modulith · JPA · Flyway · PostgreSQL, 화면은 React · Vite · Tailwind
- 모듈: masterdata, intake, rebate, relatedparty, approval, clarification, receivables, payment, audit, console
  - 모듈 사이의 상태는 이벤트로 전달합니다.
  - 이벤트는 같은 트랜잭션의 발행 기록에 저장됩니다(Transactional Outbox).
- 외부 연동(은행, 대리점 통지, AI)만 포트·어댑터로 분리했습니다. 은행과 통지는 모의 어댑터입니다.
- 테스트: Testcontainers PostgreSQL 기반 통합 테스트 46개(`./gradlew test`)
  - 그중 1개(대회 배포 원본과 대조)는 원본 자료가 있는 환경에서만 실행됩니다.

## 공개 범위

- 이 저장소는 합성 데이터와 모의 처리로 만든 시연 환경입니다. 로그인이 없고, 역할은 요청 헤더로 흉내 냅니다.
- 대회에서 배포한 문제 자료 원문은 이 저장소에 넣지 않았습니다.
- 앱 구동에 필요한 원본 데이터 일부만 `app/src/main/resources/original/`에 들어 있습니다.
